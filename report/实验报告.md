## 第 1 页　任务与方法 / 本人贡献

**目标**：给定图像与训练好的参数 theta，不用深度学习框架，仅用 NumPy 手写 ViT-B-32 图像塔前向计算，
把每张图编码为 512 维单位长度特征，并与独立 Torch FP32 参考逐阶段对齐；不训练、不把参考数组当输入。

| 环节 | 输入 → 输出 | 关键运算 |
| --- | --- | --- |
| 预处理（提供） | 图片 → [B,3,224,224] | 双三次最短边缩放、中心裁剪、逐通道标准化 |
| patchify（TODO-01） | → [B,49,3072] | 7×7 网格重排，块内 C,H,W 展开 |
| embed（TODO-05） | → [B,50,768] | 无偏置 patch 投影、前置 CLS、加位置向量 |

| 输出头（TODO-06） | → [B,512] | 取 CLS、ln_post、visual.proj、单位化 |

## 第 2 页　可复现性

**环境**：操作系统 Windows 11, Python 3.14.3（课程要求 ≥ 3.9）, NumPy 2.4.3（requirements: numpy>=1.24,<3）, Pillow 12.3.0（requirements: Pillow>=9.2,<13）, 其它 imageio 仅课堂示例需要；无 GPU、无 PyTorch、无 OpenCLIP、无联网。
依赖清单 `requirements.txt`：numpy>=1.24,<3；Pillow>=9.2,<13；imageio>=2.31,<3。
安装：`python -m pip install -r requirements.txt`。

**关键参数**：输入尺寸=224×224 RGB，[B,3,224,224] float32; patch=32×32，7×7=49 个，展平 3072 维; Transformer=width 768 / heads 12 / head_dim 64 / layers 12 / MLP 3072; 序列与输出=CLS + 49 patch = 50 token；输出 512 维、L2 范数 1; 数值约定=LayerNorm eps=1e-5；精确 GELU(erf)；线性权重 [out,in]，visual.proj 为 [in,out]; 归一化常数=mean=(0.48145466,0.4578275,0.40821073)，std=(0.26862954,0.26130258,0.27577711)。

**数据获取**：仓库含 10 张图片（约 412 KB）、config.json、images.json、两个 manifest.json。
`weights/image_encoder.npz`（约 311 MiB / 152 个张量）与 `assets/reference_outputs.npz`（约 7.3 MiB）
超过 GitHub 单文件 100 MB 上限，按 README 第 3 节从课程附件复制回对应目录，
`check.py --stage assets` 自动校验 SHA-256。参考输出只被 check.py 读取。

**运行步骤**（仓库根目录）：

```bash
python -m pip install -r requirements.txt
python transformer_steps.py
python check.py --stage assets
python check.py --stage patches
python check.py --stage tokens
python check.py --stage block0
python check.py --stage last_tokens
python check.py --stage output
python check.py --stage batch
python check.py --stage all
python run.py --output results/output_tokens.npz
```

**判定**：shape 一致、float32、有限值，abs(actual−reference) ≤ atol + rtol·abs(reference)；
atol：output/batch 2e-5、内部 token 2e-4、preprocess 2e-6，rtol=2e-4；输出每行范数为 1。
实测 `--stage all` 约 2 分 13 秒。

最终输出最大误差 5.439e-07（约为容差 2e-5 的 1/37）。batch 使用 [1,0,1] 乱序 + 重复输入也通过。

**图表**：`results/evidence_figure.png`（左：各阶段最大绝对误差对数柱状图；右：输出特征 10×10 余弦相似度热力图）。

**结论**：纯 NumPy 前向与独立 Torch FP32 参考在全部中间阶段及最终输出一致，误差远小于容差；
单位化、批量乱序与重复图等边界行为通过，可直接复用到期末项目图像塔。

## 第 4 页　分析与反思 / 提交信息

**5.1 解释与比较**：误差主要来自矩阵乘累加顺序与 float32 舍入（中间阶段约 1e-5）；
经 ln_post、投影与单位化后回落到约 5e-7，未被 12 层放大。preprocess/patches 为 0，
因为前者由课程代码提供、后者是纯重排。相比直接调用 PyTorch，NumPy 版逐层展开便于核对 shape，代价是速度较慢。

**5.2 一处 shape 变化与一个易错点**：split_heads 为
[B,N,768] → reshape(B,N,12,64) → transpose(0,2,1,3) → [B,12,N,64]；
合并严格逆操作 transpose(0,2,1,3).reshape(B,N,768)。k 是 4D，scores 只能交换最后两轴
`k.transpose(0,1,3,2)`，不能像 2D 教学示例写 k.T。易错点：其它权重 [out,in] 需转置，
但 visual.proj 已是 [in,out]=[768,512]，转置会维度不兼容（依据 config.json 的
output_projection_layout 确认）；第一条残差必须加在原始 x 而非 norm1(x)。

**5.3 失败与修复**：本机初始仅有 NumPy，首次 `check.py` 在 load_images() 处报
`ModuleNotFoundError: No module named 'PIL'`；按 requirements.txt 补装 Pillow 12.3.0 后
8 阶段一次通过。数值校验本身未出现 FAIL，得益于按阶段逐个排查。

**5.4 局限与改进**：（1）helpers.GELU 用 Python 循环逐元素 math.erf，全量校验约 2 分 13 秒，
可改用向量化 erf 并做等价性对照；（2）326 MB 权重超过 GitHub 单文件上限，
本仓库用 .gitignore 排除并在 README 写明获取方法与 SHA-256 校验，必要时用 Git LFS；
（3）仅图像塔、参数固定，无文本塔/训练/下游评测，后续可做跨模态检索与更多图片回归测试；
（4）注意力矩阵 [B,12,50,50] 内存随 B 线性增长，大批量可考虑分块。
